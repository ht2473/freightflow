# Быстрый запуск

Развёртывание с нуля занимает 2–5 минут. PostgreSQL, Docker и библиотеки
геообработки **не нужны**: система поставляется с готовой базой SQLite.

---

## Windows

**Требуется:** Windows 10 или 11. Всё остальное сценарий предложит установить сам.

```powershell
cd путь\к\freightflow

# Разрешаем выполнение сценариев в текущем окне терминала
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force

# Развёртывание: проверит Python, при необходимости предложит установить,
# создаст окружение, загрузит данные и подготовит демонстрационный стенд
.\deploy\setup.ps1

# Запуск
.\deploy\run.ps1
```

Откройте <http://127.0.0.1:8000/>

> **Если файлы получены архивом**, снимите с них метку «загружено из интернета» —
> иначе Windows заблокирует запуск сценариев:
> ```powershell
> Get-ChildItem -Recurse | Unblock-File
> ```

## Linux и macOS

**Требуется:** Python 3.12 или новее.

```bash
cd путь/к/freightflow

./deploy/setup.sh
.venv/bin/python backend/manage.py runserver
```

Если Python устарел:

```bash
# Ubuntu / Debian
sudo apt install python3.12 python3.12-venv

# macOS
brew install python@3.12
```

## Учётные записи

Пароль у всех — `FreightFlow2026`.

| Логин | Роль | Что доступно |
|---|---|---|
| `viewer` | Наблюдатель | Реестры, карта, аналитика, избранное |
| `analyst` | Аналитик | Дополнительно: выгрузка отчётов, доступ к API |
| `operator` | Диспетчер | Дополнительно: ведение дорожных событий |
| `admin` | Администратор | Полный доступ, панель `/console/` |

## С чего начать осмотр

1. **Главная** — лента состояния сети под заголовком: каждый сегмент это участок дороги, наведите курсор
2. **Шапка** — переключатель оформления: три режима, у каждого свой знак
3. **Шапка** — переключатель языка: интерфейс переходит на английский целиком
4. **Карта** — включите слои, нажмите «Что рядом с точкой» и укажите место
5. **Аналитика** → индекс нагрузки → прогноз → сценарный расчёт
6. Войдите как `analyst`, откройте реестр объектов, выгрузите **XLSX**
7. Войдите как `admin`, откройте `/console/quality/` — семь автоматических проверок

## Публикация в своём GitHub

Работа ведётся в локальном репозитории и публикуется одним `push` со всей
историей. Создайте **пустой** репозиторий на GitHub (без README и `.gitignore`)
и выполните:

```powershell
git remote add origin https://github.com/ВАШ_АККАУНТ/freightflow.git
git push -u origin main
```

Даты коммитов при этом сохраняются: важно, когда работа выполнялась,
а не когда репозиторий стал публичным.

> Прежде здесь описывался сценарий `setup-history.ps1`, создававший сто
> коммитов задним числом. Он удалён из проекта. Такая история распознаётся
> тривиально — по совпадающим меткам времени автора и коммитера и по
> неправдоподобно ровному распределению, — а история настоящей работы
> набирается сама и подделки не требует.

## Если что-то пошло не так

| Симптом | Решение |
|---|---|
| Сценарий не запускается | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force` |
| `ModuleNotFoundError: django` | Зависимости не установлены: `.\deploy\setup.ps1 -Force` |
| `ImproperlyConfigured: FF_SECRET_KEY` | Отсутствует `.env`: `.\deploy\setup.ps1` |
| Страницы без оформления | `.venv\Scripts\python.exe backend\manage.py collectstatic --noinput --clear` |
| Порт занят | `.\deploy\run.ps1 -Port 8080` |
| Ошибки установки под Python 3.14 | Сценарий сам берёт 3.12 через `uv`; при ручной установке укажите `uv venv .venv --python 3.12` |
| Английский не применяется | Файл переводов не собран — нужен `gettext`; на Windows он входит в поставку готовым |
| Знак оформления не меняется | Кеш браузера: обновите страницу через `Ctrl+F5` |

Подробности — в [README.md](README.md) и каталоге [docs/](docs/).
