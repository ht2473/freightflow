# Реестр рисков проекта «ГрузПоток»

Оценка вероятности и влияния — по трёхуровневой шкале. Уровень риска
определяется произведением: низкий (1–2), средний (3–4), высокий (6–9).

| Шкала | Вероятность | Влияние |
|---|---|---|
| 1 — низкая | Менее 25 % | Задержка до 1 дня, обходной путь очевиден |
| 2 — средняя | 25–60 % | Задержка 2–4 дня, требуется переработка |
| 3 — высокая | Свыше 60 % | Задержка свыше недели либо невыполнение требования |

---

## Технические риски

### Р-01. Сложность установки библиотек геообработки

| | |
|---|---|
| **Вероятность** | 3 (высокая) |
| **Влияние** | 3 (высокое) |
| **Уровень** | 9 — высокий |
| **Состояние** | Устранён |

**Описание.** Установка GDAL на Windows требует подбора совместимых сборок и
настройки переменных окружения. Ошибка `OSError: could not find the GDAL
library` — распространённое препятствие, способное заблокировать разработку
на неопределённый срок.

**Мера предупреждения.** Отказ от `django.contrib.gis` в пользу собственного
тонкого слоя поверх возможностей СУБД. Решение принято на этапе выбора
технических средств, до начала разработки.

**Результат.** Установка сводится к `pip install`. Система разворачивается на
чистой машине Windows без системных библиотек. Обоснование — в
[ADR-0001](adr/0001-geometry-without-gdal.md).

### Р-02. Расхождение поведения СУБД

| | |
|---|---|
| **Вероятность** | 3 (высокая) |
| **Влияние** | 2 (среднее) |
| **Уровень** | 6 — высокий |
| **Состояние** | Наступил, устранён |

**Описание.** Система работает на PostgreSQL с PostGIS и на SQLite.
Пространственные запросы используют разные выражения SQL; ошибка в одном из
вариантов не обнаруживается проверкой другого.

**Мера предупреждения.** Обязательный прогон полного набора автотестов на
обоих контурах в среде непрерывной интеграции. Отдельная проверка совпадения
результатов пространственного поиска.

**Фактическое проявление.** Два дефекта, оба выявлены только на PostgreSQL:

- [Б-09](BUG_REPORTS.md#б-09) — неоднозначная ссылка на колонку геометрии при
  соединении со справочником округов, имеющим одноимённую колонку;
- [Б-10](BUG_REPORTS.md#б-10) — неприменимость инструкции `TRUNCATE` внутри
  открытой транзакции.

**Оценка меры предупреждения.** Мера сработала: оба дефекта обнаружены до
развёртывания. Дефект Б-09 показателен тем, что на контуре разработки не
проявлялся вовсе, а при иных обстоятельствах привёл бы к тихо неверному
результату вместо отказа запроса.

**Недостаток исполнения.** Прогон на промышленном контуре выполнялся не при
каждой итерации, а на завершающем этапе. Более ранняя проверка позволила бы
выявить дефекты раньше и с меньшими затратами на исправление.

**Результат.** Расхождение расстояний при поиске ближайших не превышает
0,004 км (ТК-48). Полный набор автотестов пройден на обоих контурах.

### Р-03. Коллизия имён при определении моделей

| | |
|---|---|
| **Вероятность** | 2 (средняя) |
| **Влияние** | 3 (высокое) |
| **Уровень** | 6 — высокий |
| **Состояние** | Наступил, устранён |

**Описание.** Имя обратной связи, совпадающее с именем стандартного
менеджера модели, приводит к его перекрытию и полной неработоспособности
приложения.

**Мера предупреждения.** Не была предусмотрена — риск не был выявлен на этапе
планирования.

**Фактическое проявление.** Дефект [Б-04](BUG_REPORTS.md#б-04): имя
`related_name="objects"` перекрыло менеджер `District.objects`. Обнаружен при
формировании миграций, устранён в тот же день переименованием связи в
`facilities`.

**Извлечённый урок.** Имена обратных связей следует проверять на совпадение
с атрибутами модели, определяемыми фреймворком. Естественность имени с точки
зрения предметной области не является достаточным основанием для его выбора.

### Р-04. Недостаточная производительность на объёмных данных

| | |
|---|---|
| **Вероятность** | 2 (средняя) |
| **Влияние** | 2 (среднее) |
| **Уровень** | 4 — средний |
| **Состояние** | Наступил, устранён |

**Описание.** Страницы с агрегатами выполняют запросы по всем таблицам
наблюдений. При объёме в десятки тысяч записей время отклика может превысить
допустимое.

**Меры предупреждения.**

- вынос всех агрегатов в отдельный слой с кешированием на пять минут;
- составные индексы под типовые запросы, включая частичные;
- предварительная загрузка связанных записей (`select_related`) во всех
  выборках, отображаемых в таблицах;
- проверка на расширенном наборе данных (около 78 000 записей);
- нагрузочное испытание при 50 одновременных пользователях.

**Фактическое проявление.** При проверке на расширенном наборе (20 000
объектов инфраструктуры) два обращения превысили пороговые значения:

| Операция | Было | Порог | Стало |
|---|---|---|---|
| Слой объектов карты | 2341 мс | 2000 мс | 758 мс |
| Поиск объектов в радиусе | 1080 мс | 1200 мс | 128 мс |

Причины оказались однотипными: объекты модели создавались для всех записей
реестра, тогда как в результат попадала лишь их часть. В слое карты
ограничение накладывалось после материализации выборки, в поиске ближайших —
разбирались координаты всех записей.

**Мера устранения.** Оба места переписаны на два прохода: сначала читается
пара «ключ — геометрия» без создания объектов модели, затем выборка сужается
по отобранным ключам. В поиске ближайших дополнительно добавлено отсечение по
прямоугольнику: сравнение чисел дешевле вычисления расстояния по ортодромии.

**Результат.** Все девятнадцать контрольных обращений укладываются в
пороговые значения на расширенном наборе; превышений нет (ТК-50). Отсутствие
запросов вида N+1 подтверждено автотестом
`test_selectors.py::TestLatestConditions::test_related_objects_prefetched`.

### Р-05. Невоспроизводимость результатов кластеризации

| | |
|---|---|
| **Вероятность** | 2 (средняя) |
| **Влияние** | 2 (среднее) |
| **Уровень** | 4 — средний |
| **Состояние** | Устранён |

**Описание.** Метод k-средних зависит от начального выбора центров. При
случайной инициализации повторное обращение к странице типологии давало бы
различный состав групп, что подорвало бы доверие к разделу.

**Мера предупреждения.** Фиксация зерна генератора случайных чисел,
инициализация по схеме k-means++, отдельный автотест воспроизводимости.

**Результат.** Состав групп не меняется при повторных обращениях (ТК-19,
автотест `test_analytics.py::TestKMeans::test_deterministic_with_fixed_seed`).

### Р-06. Отсутствие кириллического шрифта при формировании PDF

| | |
|---|---|
| **Вероятность** | 2 (средняя) |
| **Влияние** | 2 (среднее) |
| **Уровень** | 4 — средний |
| **Состояние** | Наступил, устранён |

**Описание.** Библиотека формирования PDF не содержит кириллических
начертаний; в зависимости от состава шрифтов целевой системы текст может
оказаться нечитаемым.

**Фактическое проявление.** Дефект [Б-02](BUG_REPORTS.md#б-02).

**Мера устранения.** Перебор нескольких путей к системным шрифтам с
регистрацией первого найденного и запасным вариантом при отсутствии всех.
В образ контейнера добавлен пакет шрифтов.

## Проектные риски

### Р-07. Единственный исполнитель

| | |
|---|---|
| **Вероятность** | 3 (высокая) |
| **Влияние** | 2 (среднее) |
| **Уровень** | 6 — высокий |
| **Состояние** | Контролируется |

**Описание.** Проект выполняется одним человеком. Отсутствует возможность
параллельного исполнения работ и взаимной проверки решений.

**Меры предупреждения.**

- декомпозиция работ на пакеты продолжительностью не более двух дней;
- выполнение работ с наибольшей технической неопределённостью в первую
  очередь (пространственный слой);
- автоматизация проверок: набор автотестов заменяет взаимную проверку;
- оформление существенных решений записями ADR — это вынуждает
  формулировать основания явно, что частично компенсирует отсутствие
  обсуждения.

### Р-08. Расширение объёма работ

| | |
|---|---|
| **Вероятность** | 2 (средняя) |
| **Влияние** | 3 (высокое) |
| **Уровень** | 6 — высокий |
| **Состояние** | Контролируется |

**Описание.** Стремление добавить возможности, не входящие в подтверждённые
требования, приводит к превышению срока при неизменном объёме обязательных
работ.

**Меры предупреждения.**

- фиксация перечня требований в уставе проекта с указанием способа проверки
  каждого;
- явное определение границ проекта, включая перечень работ, не входящих в
  объём;
- сопоставление фактического состава реализованного с перечнем требований
  при завершении каждого этапа.

**Результат.** Реализованы все четырнадцать функциональных требований;
работы, не входящие в объём, не выполнялись.

### Р-09. Недостаточность содержательного наполнения

| | |
|---|---|
| **Вероятность** | 2 (средняя) |
| **Влияние** | 2 (среднее) |
| **Уровень** | 4 — средний |
| **Состояние** | Контролируется |

**Описание.** Требования предусматривают содержательные тексты вместо
заполнителей. Подготовка таких текстов трудоёмка и при недостатке внимания
откладывается на завершающий этап, где времени на неё не остаётся.

**Мера предупреждения.** Выделение подготовки наполнения в отдельный пакет
работ (5.4) с собственной оценкой трудоёмкости — 10 часов, наравне с
разработкой функций.

**Результат.** Подготовлены разделы методологии, справки и описания системы,
пять аналитических материалов, тексты пояснений на всех страницах.

## Риски эксплуатации

### Р-11. Неполнота исходных данных

| | |
|---|---|
| **Вероятность** | 3 (высокая) |
| **Влияние** | 2 (среднее) |
| **Уровень** | 6 — высокий |
| **Состояние** | Контролируется |

**Описание.** Сведения из внешних источников поступают с пропусками: объекты
без координат, без указания мощности, инциденты без привязки к участку.
Пропуски искажают результаты агрегации.

**Меры предупреждения.**

- раздел контроля качества с семью автоматическими проверками;
- публикация показателей полноты в открытом доступе — на страницах
  источников данных и методологии;
- явное указание в документации, какие именно выводы искажаются при
  наличии пропусков.

**Обоснование подхода.** Скрывать неполноту данных недопустимо: пользователь,
не осведомлённый о пропусках, может принять решение на основании заниженного
показателя обеспеченности округа.

## Сводка

| Уровень | Всего | Предотвращён | Контролируется | Наступил и устранён |
|---|---|---|---|---|
| Высокий (6–9) | 6 | 1 | 3 | 2 |
| Средний (3–4) | 6 | 1 | 3 | 2 |
| Низкий (1–2) | 1 | — | 1 | — |
| **Итого** | **13** | **2** | **7** | **4** |

Четыре риска реализовались (Р-02, Р-03, Р-04, Р-06); все устранены в день
обнаружения без влияния на срок проекта.

**Наблюдение по итогам.** Три из четырёх реализовавшихся рисков относятся к
условиям, отличным от условий разработки: другая СУБД (Р-02), больший объём
данных (Р-04), иной состав системных шрифтов (Р-06). Меры предупреждения по
всем трём были предусмотрены и сработали — но применялись на завершающем
этапе, а не при каждой итерации.

Основной извлечённый урок: проверку в условиях, приближенных к промышленным,
следует включать в регламент каждой итерации. Стоимость исправления дефекта
на восьмой неделе существенно выше, чем на третьей, а вероятность его
обнаружения при проверке только в условиях разработки близка к нулю.

Риск Р-03 не был выявлен на этапе планирования вовсе — это отражено в
реестре как извлечённый урок, а не скрыто задним числом.
