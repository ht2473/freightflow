# Словарь данных ИС «ГрузПоток»

Описание тринадцати таблиц предметной области. Схема приведена в
`db/001_schema.sql`.

**Условные обозначения:** ПК — первичный ключ, ВК — внешний ключ,
NN — обязательное поле.

---

## Общие соглашения

| Аспект | Принятое решение |
|---|---|
| Система координат | WGS-84 (EPSG:4326), порядок — долгота, широта |
| Отметки времени | С указанием часового пояса, хранятся в UTC, отображаются в Europe/Moscow |
| Денежные и весовые величины | `NUMERIC` с явной точностью — не `FLOAT`, во избежание накопления погрешности |
| Удаление справочных записей | Запрещено при наличии ссылок (`ON DELETE RESTRICT`) |
| Удаление источника данных | Ссылка обнуляется (`ON DELETE SET NULL`) — сведения сохраняются |

## 1. `districts` — административные округа

Справочник территориального деления города.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `name` | `VARCHAR(100)` | NN, уникально | Наименование округа |
| `short_name` | `VARCHAR(20)` | NN, уникально | Общепринятая аббревиатура (ЦАО, САО) |
| `area_sq_km` | `NUMERIC(10,2)` | > 0 | Площадь, км² |
| `population` | `INTEGER` | ≥ 0 | Численность населения, человек |
| `geom` | `GEOMETRY(MultiPolygon,4326)` | | Границы округа |
| `center` | `GEOMETRY(Point,4326)` | | Условный центр для размещения подписи на карте |

**Производные характеристики:** плотность населения (отношение численности к
площади), центр для карты (координаты `center` либо центроид границ).

## 3. `cargo_categories` — категории грузов

Классификатор перевозимых грузов с указанием класса опасности.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `code` | `VARCHAR(50)` | NN, уникально | Машинный код |
| `name` | `VARCHAR(100)` | NN | Наименование категории |

## 4. `data_sources` — источники данных

Реестр источников, наполняющих систему. Источник объявляется здесь только
вместе с работающим загрузчиком: запись означает, что данные оттуда
действительно поступают, а не что такая возможность предполагается.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `code` | `VARCHAR(32)` | NN, уникально | Машинный код источника |
| `name` | `VARCHAR(200)` | NN | Наименование организации или системы |
| `source_type` | `VARCHAR(32)` | NN | Тип: `api`, `csv`, `open_data`, `gis_service`, `manual`, `model` |
| `url` | `VARCHAR(500)` | | Адрес источника |
| `update_frequency` | `VARCHAR(32)` | | Периодичность: `hourly`, `daily`, `weekly`, `monthly`, `quarterly` |
| `is_active` | `BOOLEAN` | NN | Признак действующего источника |

Расчётная модель (`model`) стоит в одном ряду с внешними службами намеренно:
она тоже наполняет таблицы системы, и вынесение её за пределы реестра скрыло
бы происхождение части сведений.

## 6. `road_segments` — участки улично-дорожной сети

Одной записи соответствует именованная магистраль целиком, а не отрезок между
перекрёстками: в исходных данных дорога разбита на сотни частей по сменам
характеристик и по направлениям движения.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `name` | `VARCHAR(200)` | NN | Наименование магистрали |
| `ref` | `VARCHAR(32)` | | Учётный номер трассы: М-4, А-103 |
| `road_class` | `VARCHAR(32)` | NN | Класс: `highway`, `arterial`, `collector` |
| `lanes` | `SMALLINT` | 1–16 | Число полос движения |
| `length_km` | `NUMERIC(8,2)` | > 0 | Суммарная длина проезжих частей, км |
| `length_origin` | `VARCHAR(16)` | | Происхождение протяжённости |
| `allows_hgv` | `BOOLEAN` | | Разметка допускает грузовое движение; `NULL` — сведений нет |
| `in_freight_frame` | `BOOLEAN` | | Входит в грузовой каркас; `NULL` — сведений нет |
| `freight_frame_kind` | `VARCHAR(16)` | | Роль в каркасе: кольцевая, вылетная, хордовая |
| `segment_count` | `INTEGER` | NN | Число частей, из которых собрана магистраль |
| `speed_limit_kmh` | `SMALLINT` | 5–130 | Разрешённая скорость, км/ч |
| `district_id` | `INTEGER` | ВК → `districts` | Преобладающий округ |
| `geom` | `geometry(MultiLineString, 4326)` | | Геометрия магистрали |
| `source_updated_at` | `TIMESTAMPTZ` | | Дата выгрузки источника |
| `source_id` | `INTEGER` | ВК → `data_sources` | Источник сведений |

**Производные характеристики:** условная пропускная способность как
произведение числа полос на разрешённую скорость.

Протяжённость измеряется как суммарная длина проезжих частей: разделённая
проезжая часть размечена двумя независимыми линиями, и сведение их к одной
осевой потребовало бы допущения, неверного на части магистралей.

## 10. `freight_flow_stats` — статистика перевозок грузов

Таблица ведёт ряд в двух разрезах. Внутригородской привязан к округу, маршруту
и категории груза; ведомственный приходит в разрезе территорий и круга
перевозчиков, без деления по направлениям. Обе формы описывают одну величину —
объём перевезённого груза, — и различает их набор заполненных признаков.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `period_date` | `DATE` | NN | Начало периода |
| `period_type` | `VARCHAR(16)` | NN | Тип: `day`, `week`, `month`, `quarter`, `year` |
| `route_id` | `INTEGER` | ВК → `cargo_routes` | Маршрут |
| `district_id` | `INTEGER` | ВК → `districts` | Округ |
| `cargo_category_id` | `INTEGER` | ВК → `cargo_categories` | Категория груза |
| `territory` | `VARCHAR(120)` | NN | Территория ведомственного ряда; у внутригородского пусто |
| `direction` | `VARCHAR(16)` | NN | Направление: `in`, `out`, `transit`, `total` |
| `scope` | `VARCHAR(16)` | NN | Круг перевозчиков: `all`, `commercial` |
| `volume_tons` | `NUMERIC(14,2)` | ≥ 0 | Объём перевозок, т |
| `turnover_ton_km` | `NUMERIC(18,2)` | ≥ 0 | Грузооборот, т·км |
| `vehicle_count` | `INTEGER` | ≥ 0 | Число рейсов |
| `origin` | `VARCHAR(16)` | | Происхождение: `measured`, `derived`, `modelled` |
| `avg_speed_kmh` | `NUMERIC(6,2)` | ≥ 0 | Средняя скорость доставки, км/ч |
| `source_id` | `INTEGER` | ВК → `data_sources` | Источник сведений |
| `external_key` | `VARCHAR(120)` | NN | Ключ записи в источнике |

**Индексы:** по периоду (убывание), составной по паре «округ — период»,
уникальный частичный по паре «источник — ключ записи» при непустом ключе.

**Производные характеристики:** средняя загрузка рейса (объём, делённый на
число рейсов), среднее расстояние перевозки (грузооборот, делённый на объём).

Ряды разных территорий сложению не подлежат: город входит в федеральный округ,
округ — в страну. Ряды разного круга перевозчиков описывают разные
совокупности и также не складываются.

## 11. `restriction_zones` — зоны ограничения движения

Постановление Правительства Москвы № 379-ПП от 22.08.2011 определяет три зоны
не координатами, а кольцевыми магистралями. Границы поэтому не задаются
отдельным набором данных, а выводятся из геометрии самих колец — так, как их
определяет нормативный акт.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `code` | `VARCHAR(16)` | NN, уникально | Обозначение зоны: `mkad`, `ttk`, `sk` |
| `name` | `VARCHAR(120)` | NN | Наименование |
| `short_name` | `VARCHAR(32)` | NN | Аббревиатура |
| `description` | `TEXT` | | Условия въезда словами |
| `level` | `SMALLINT` | NN, ≥ 1 | Уровень вложенности: 1 — внешняя зона |
| `boundary_road_id` | `INTEGER` | ВК → `road_segments` | Кольцевая магистраль, задающая границу |
| `permit_required_from_tons` | `NUMERIC(6,2)` | NN | РММ, начиная с которой требуется пропуск |
| `min_ecological_class` | `SMALLINT` | | Наименьший допустимый экологический класс |
| `seasonal_limit_tons` | `NUMERIC(6,2)` | | Сезонное ограничение с 1 мая по 1 октября |
| `fine_rubles` | `INTEGER` | | Ответственность за нарушение, руб. |
| `legal_basis` | `VARCHAR(200)` | | Основание — реквизиты нормативного акта |
| `geom` | `geometry(MultiPolygon, 4326)` | | Граница зоны |
| `area_sq_km` | `NUMERIC(10,2)` | | Площадь зоны, км² |
| `perimeter_km` | `NUMERIC(8,2)` | | Периметр границы, км |
| `geometry_origin` | `VARCHAR(16)` | | Происхождение геометрии |
| `source_updated_at` | `TIMESTAMPTZ` | | Дата выгрузки, из которой собрана граница |

**Индексы:** пространственный по границе зоны.

Пропуск во внутреннюю зону действует и во внешних, поэтому вложенность зон
проверяется при каждой загрузке: нарушение означает, что какая-то из границ
собрана неверно.

## 12. `etl_log` — журнал процедур загрузки

Одна строка — одно прохождение конвейера по одному набору данных. Счётчики
разделены: по соотношению «создано / обновлено / без изменений» видно, работает
ли инкрементальная загрузка — при исправном источнике повторный запуск
оставляет почти всё без изменений.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `started_at` | `TIMESTAMPTZ` | NN | Начало выполнения |
| `finished_at` | `TIMESTAMPTZ` | | Окончание; `NULL` — процедура выполняется |
| `source_id` | `INTEGER` | ВК → `data_sources` | Источник данных |
| `pipeline` | `VARCHAR(64)` | NN | Обозначение набора в реестре конвейеров |
| `target_table` | `VARCHAR(64)` | NN | Целевая таблица |
| `trigger` | `VARCHAR(16)` | NN | Начало: `schedule`, `console`, `upload`, `cli` |
| `actor_id` | `INTEGER` | ВК → `auth_user` | Кто начал загрузку |
| `parameters` | `VARCHAR(200)` | NN | Условия запуска |
| `records_loaded` | `INTEGER` | ≥ 0 | Записано: создано и обновлено |
| `records_created` | `INTEGER` | ≥ 0 | Появилось новых записей |
| `records_updated` | `INTEGER` | ≥ 0 | Изменилось существующих |
| `records_unchanged` | `INTEGER` | ≥ 0 | Совпало с уже имеющимся |
| `records_removed` | `INTEGER` | ≥ 0 | Удалено при приведении к составу источника |
| `records_errors` | `INTEGER` | ≥ 0 | Отклонено проверками качества |
| `status` | `VARCHAR(16)` | NN | Итог: `running`, `success`, `partial`, `failed` |
| `error_message` | `TEXT` | | Замечания загрузки |

**Индексы:** по времени начала (убывание).

**Производные характеристики:** длительность выполнения в минутах, доля
отклонённых записей в процентах, общее число прошедших конвейер записей.

## 13. `etl_rejects` — карантин загрузки

Запись источника, не прошедшая проверку качества. В реестр она не попадает,
но и не пропадает: сохраняются причина, положение в источнике и исходное
содержимое — по одному счётчику ошибок исправлять источник невозможно.

| Поле | Тип | Ограничения | Описание |
|---|---|---|---|
| `id` | `SERIAL` | ПК | Идентификатор |
| `run_id` | `INTEGER` | NN, ВК → `etl_log`, каскад | Загрузка, отклонившая запись |
| `position` | `VARCHAR(120)` | NN | Элемент выгрузки либо номер строки файла |
| `record_key` | `VARCHAR(200)` | NN | Ключ записи |
| `check_code` | `VARCHAR(64)` | NN | Код не пройденной проверки |
| `message` | `VARCHAR(500)` | NN | Формулировка причины |
| `payload` | `TEXT` | | Исходная запись в том виде, в каком поступила |
| `created_at` | `TIMESTAMPTZ` | NN | Время отложения |
| `reviewed_at` | `TIMESTAMPTZ` | | Отметка о разборе |
| `reviewed_by_id` | `INTEGER` | ВК → `auth_user` | Кто разобрал |

**Индексы:** по времени отложения (убывание), по коду проверки.

## Представления

Помимо таблиц схема содержит два представления (`db/003_views.sql`).

### `v_district_summary`

Агрегированные показатели округов: число объектов, суммарная мощность
хранения, протяжённость дорожной сети, объём грузопотока.

### `v_current_traffic`

Последний замер обстановки для каждого участка сети с присоединёнными
сведениями об участке и округе.

у системы нет, и каждое число прослеживается до источника, из которого оно
получено.
