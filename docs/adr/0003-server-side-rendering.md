# ADR-0003. Отрисовка страниц на сервере

- **Статус:** принято
- **Дата:** 2026-06-25
- **Контекст:** выбор архитектуры клиентской части

## Контекст

Требовалось определить способ построения интерфейса: отрисовка на сервере
средствами шаблонов Django либо одностраничное приложение на клиентском
фреймворке, получающее данные через REST API.

## Рассмотренные варианты

### Вариант 1. Одностраничное приложение (React, Vue)

*Достоинства:* богатые возможности взаимодействия, переходы между разделами
без перезагрузки, развитая экосистема компонентов.

*Недостатки:*

- требуется сборщик и отдельный конвейер публикации;
- содержание страниц недоступно поисковым системам без отрисовки на сервере;
- объём передаваемого кода на порядок больше;
- разграничение доступа приходится дублировать на клиенте и на сервере;
- для системы, где преобладает чтение таблиц и карточек, преимущества
  реализуются лишь частично.

### Вариант 2. Отрисовка на сервере (принят)

*Достоинства:*

- страница приходит готовой; время до первого содержательного отображения
  минимально;
- разграничение доступа реализовано в одном месте — в представлениях;
- отсутствует этап сборки: изменение шаблона видно сразу;
- содержание доступно поисковым системам и программам чтения с экрана;
- объём передаваемого кода минимален.

*Недостатки:*

- переходы между разделами сопровождаются перезагрузкой страницы;
- сложные взаимодействия требуют написания сценариев вручную.

## Решение

Принят вариант 2 с добавлением клиентского поведения там, где оно
действительно необходимо: интерактивная карта, построение графиков,
переключение оформления, работа меню на узких экранах.

REST API при этом реализован и документирован полностью — но как интерфейс
для внешних потребителей, а не как источник данных для собственного
интерфейса. Такое разделение снимает противоречие между удобством внутренней
разработки и требованиями к внешнему контракту: API может развиваться,
сохраняя обратную совместимость, независимо от изменений в шаблонах.

## Последствия

**Положительные.** Отсутствие сборщика упрощает развёртывание и сопровождение.
Проверка прав доступа выполняется единожды на сервере, что подтверждается
автотестами. Страницы работоспособны при отключённых сценариях — за
исключением карты, что для картографического раздела неизбежно.

**Отрицательные.** Наложение условий отбора вызывает перезагрузку страницы.
Для смягчения формы отбора отправляются автоматически при изменении значения
списка — пользователю не требуется отдельное нажатие кнопки.
