# ГрузПоток · FreightFlow

**Информационная система мониторинга и анализа логистической инфраструктуры города Москвы**

Система объединяет в единой среде сведения о складских мощностях и грузовых
терминалах, состоянии улично-дорожной сети, грузовых коридорах и объёмах
перевозок. Разрозненные ведомственные выгрузки приводятся к общей схеме,
дополняются пространственной привязкой и становятся доступны через
веб-интерфейс, интерактивную карту и программный интерфейс REST.

> **Нужно только запустить?** См. [QUICKSTART.md](QUICKSTART.md) — одна команда, 2–5 минут.

## Возможности

**Реестры и справочники.** Объекты инфраструктуры, административные округа,
участки дорожной сети, грузовые маршруты, категории грузов, источники данных.
Каждый реестр поддерживает отбор по нескольким признакам, поиск, сортировку и
постраничный вывод.

**Интерактивная карта.** Пять независимо подключаемых слоёв: объекты
инфраструктуры, дорожная сеть с окраской по загруженности, дорожные события,
грузовые коридоры и округа с агрегированными показателями. Предусмотрен поиск
объектов в заданном радиусе от произвольной точки.

**Мониторинг дорожной обстановки.** Текущая загруженность каждого участка,
средний суточный профиль за две недели наблюдений, распределение участков по
состояниям движения, журнал дорожных событий с оценкой серьёзности.

**Аналитика.** Композитный индекс логистической нагрузки округов, типология
методом k-средних, прогнозирование грузопотока с оценкой качества модели,
попарное сравнение округов и сценарное моделирование отклика системы на
изменение условий.

**Загрузка данных.** Единый конвейер для всех источников: получение,
приведение, проверка качества, запись, журнал. Повторный запуск обновляет
записи, а не добавляет вторые; не прошедшие проверку откладываются в карантин
с указанием причины и положения в источнике. Ряд можно прислать файлом —
он проходит тот же конвейер, что и данные внешних служб.

**Выгрузка отчётов.** Пять форматов: XLSX, DOCX, PDF, CSV и GeoJSON.
Выгружается ровно та выборка, которую пользователь видит на экране.

**Личный кабинет.** Избранное, сохранённые условия отбора с возможностью
публикации по ссылке, наборы сравнения, центр выгрузок, подписки на дорожные
события, уведомления, журнал собственных действий и управление токеном API.

**Два языка интерфейса.** Русский и английский. Переведён весь интерфейс:
навигация, заголовки разделов, подписи полей, кнопки, заголовки таблиц,
наименования показателей, оценки состояния движения, сообщения системы и
пояснительные тексты в разделах методологии и справки — свыше 1100 строк.

Наименования объектов, округов, источников данных и тексты аналитических
материалов остаются на языке исходных данных: они хранятся в базе и являются
содержанием, а не интерфейсом. Переключатель языка — в шапке страницы.

**Три режима оформления.** Тёмное, светлое и «как в системе»; каждому
соответствует собственный знак. Выбор сохраняется и применяется до первой
отрисовки страницы, без промежуточного перекрашивания.

**Панель администратора.** Управление учётными записями и ролями, ведение
справочников, обработка обращений, публикация материалов, автоматические
проверки качества данных, реестр источников с регламентом и запуском загрузки,
карточка каждой загрузки, карантин отклонённых записей, приём выгрузок
от пользователей, журнал аудита и сведения о среде выполнения.

## Быстрый запуск

Система поставляется с готовой базой SQLite, поэтому для запуска не требуется
установка СУБД.

**Windows (PowerShell):**

```powershell
git clone https://github.com/<аккаунт>/freightflow.git
cd freightflow
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
.\deploy\setup.ps1
.\deploy\run.ps1
```

**Linux и macOS:**

```bash
git clone https://github.com/<аккаунт>/freightflow.git
cd freightflow
./deploy/setup.sh
.venv/bin/python backend/manage.py runserver
```

Система доступна по адресу <http://127.0.0.1:8000/>.

Учётные записи демонстрационного стенда (пароль `FreightFlow2026`):

| Логин | Роль | Что доступно |
|---|---|---|
| `viewer` | Наблюдатель | Реестры, карта, аналитика, избранное |
| `analyst` | Аналитик | Дополнительно: выгрузка отчётов, доступ к API |
| `operator` | Диспетчер | Дополнительно: ведение дорожных событий |
| `admin` | Администратор | Полный доступ, панель управления |

## Установка

### Контур разработки

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt

cp .env.example .env                # заполните FF_SECRET_KEY
python backend/manage.py migrate
python backend/manage.py etl --all --prune
python backend/manage.py simulate_traffic --replace
python backend/manage.py setup_roles
python backend/manage.py init_demo
python backend/manage.py runserver
```

### Промышленный контур

```bash
cp .env.example .env                # укажите параметры PostgreSQL
docker compose up -d --build
```

копирования, изложен в [docs/DEPLOY.md](docs/DEPLOY.md).

## Роли и права доступа

Модель полномочий вложенная: каждая последующая роль включает права всех
предыдущих.

| Роль | Полномочия |
|---|---|
| **Наблюдатель** | Просмотр реестров, карты и аналитики; избранное; сохранённые условия отбора |
| **Аналитик** | Дополнительно: выгрузка отчётов в пяти форматах, конструктор сравнений, доступ к API по токену |
| **Диспетчер** | Дополнительно: регистрация и закрытие дорожных событий, правка карточек объектов |
| **Администратор** | Полный доступ: управление пользователями и ролями, справочники, модерация обращений, запуск загрузки данных, карантин, журнал аудита |

Ограничения реализованы на уровне представлений, а не скрытием элементов
интерфейса; соответствующие проверки входят в набор автотестов
(`tests/test_access.py`).

| `GET /api/v1/flows/` | Статистика грузопотоков |

### Подсистема загрузки

Источники у системы разной природы: программный интерфейс OpenStreetMap,
статистические публикации Росстата, перечни, ведущиеся вручную, файл,
присланный пользователем. Порядок работы с ними один и задан конвейером:
**получение → приведение → проверка → запись → журнал**.

| Набор данных | Таблица | Источник | Регламент |
|---|---|---|---|
| `osm.districts` | `districts` | OpenStreetMap, `admin_level=5` | еженедельно |
| `osm.objects` | `infrastructure_objects` | OpenStreetMap, правила отбора | еженедельно |
| `osm.roads` | `road_segments` | OpenStreetMap, `motorway\|trunk\|primary` | еженедельно |
| `osm.zones` | `restriction_zones` | Геометрия кольцевых магистралей | ежемесячно |
| `osm.corridors` | `cargo_routes` | Маршрутные отношения федеральных трасс | ежемесячно |
| `osm.roadworks` | `traffic_incidents` | `highway=construction` в границах города | ежедневно |
| `reference.frame` | `road_segments` | Перечень грузового каркаса | ежеквартально |
| `rosstat.freight` | `freight_flow_stats` | Публикация Росстата, раздел «Транспорт» | ежеквартально |
| `upload.flows` | `freight_flow_stats` | Файл CSV либо книга Excel | по присылке |

```bash
python backend/manage.py etl --list          # состав реестра с проверками
python backend/manage.py etl --all           # все наборы по порядку
python backend/manage.py etl osm.objects --prune   # привести реестр к источнику
python backend/manage.py etl --due           # то, что подошло по регламенту
python backend/manage.py etl --all --dry-run # проход без записи
```

**Инкрементальность.** Запись отыскивается по ключу источника, а её содержимое
сравнивается с поступившим. Совпадение означает, что в источнике ничего
не изменилось, и учитывается отдельным счётчиком: по доле неизменившихся
записей видно, что повторная загрузка не переписывает реестр заново.

**Проверки и карантин.** Каждый набор объявляет проверки качества — от наличия
координат до совпадения периметра зоны со справочной протяжённостью кольца.
Запись, не прошедшая проверку, в реестр не попадает, но и не пропадает:
она откладывается в карантин вместе с кодом проверки, положением в источнике
и исходным содержимым. Разбирается карантин в панели администратора.

Отбор от проверки отделён. Выгрузка намеренно шире реестра — из 2132 элементов
по Москве в реестр объектов отбирается 1088, — и отсев остальных дефектом
источника не является: он учитывается отдельно и в карантин не идёт.

**Регламент.** Периодичность объявляет сам конвейер, а срок отсчитывается
от последней успешной загрузки, поэтому неудачная попытка его не сдвигает.
Задания выполняет исполнитель Celery с планировщиком; при незаданном
`FF_CELERY_BROKER_URL` регламент ведёт системный таймер, вызывающий
`manage.py etl --due`.

### Происхождение данных

Каждый показатель сопровождается признаком происхождения, который доходит
до карточки, отчёта и выгрузки.

| Признак | Что означает | Где применяется |
|---|---|---|
| **Измерено** | получено из источника как есть | объекты, границы округов, магистрали, зоны ограничения, ряды перевозок |
| **Рассчитано** | выведено из измеренных величин | площади, протяжённости, среднее плечо доставки, агрегаты |
| **Смоделировано** | получено моделью там, где наблюдений не существует | загруженность улично-дорожной сети |

Неизмеренная величина остаётся неопределённой и выводится прочерком. Ноль
означал бы, что величина равна нулю, тогда как она попросту не публикуется
источником: мощность хранения в разметке OpenStreetMap не размечается, и
подставлять вместо неё догадку система не станет.

Загруженность дорог Москвы в открытом доступе не публикуется: ЦОДД открытого
потока не даёт, служба дорожной обстановки Яндекса платная, ЭРА-ГЛОНАСС
закрыта. Система не делает вида, что получает эти сведения, — она рассчитывает
их моделью по измеряемым характеристикам сети и помечает результат
соответствующим образом. Модель описана в `backend/analytics/simulation.py`,
а её расчёты видны в журнале загрузок наравне с обращениями к внешним службам.

Ряды перевозок приходят в разрезе территорий, вложенных одна в другую: город
входит в федеральный округ, округ — в страну. Сумма таких рядов не измеряет
ничего, поэтому раздел статистики показывает ряд одной территории, а
сопоставление даёт долю города в объёме охватывающих его территорий.

Описание полей приведено в [docs/DATA_DICTIONARY.md](docs/DATA_DICTIONARY.md).

## Развёртывание

Поддерживаются два способа.

**Контейнеры.** `docker compose up -d --build` — поднимаются PostgreSQL с
PostGIS, приложение под gunicorn, Redis, исполнитель регламентных загрузок
с планировщиком и обратный прокси nginx.

**Системная служба.** Файлы `deploy/freightflow.service` и сопутствующие
таймеры предназначены для развёртывания без контейнеров.

Регламентное обслуживание: обновление данных из источников
(`deploy/freightflow-etl.timer`), ежесуточная очистка устаревших файлов отчётов
и резервное копирование (`deploy/backup.sh`). Порядок восстановления описан
в [docs/DEPLOY.md](docs/DEPLOY.md).
